# 设计与踩坑笔记

每个里程碑改动关键设计时记一段。面试时能讲“为什么这么选”，比能跑更重要。

## 模板

### M?：做了什么

- **背景**：遇到了什么问题
- **选择**：用了什么方案，考虑过哪些替代
- **原因**：为什么选它（数据 / 约束 / 权衡）
- **代价**：这套方案哪里不好，以后什么情况下要换

---

## M1：骨架

- **背景**：需要一个能跑通的最小闭环，先建立编译—运行—验证的节奏
- **选择**：阻塞式 `accept` + 单线程，一连接一线程都还没做
- **原因**：M1 只验证 socket 生命周期（socket → bind → listen → accept → recv → send → close）是否理解正确
- **代价**：一次只能处理一个连接，没有并发；M5 会整体替换成 epoll 事件循环
